# 谷雨守护 · 离线打包说明（带「真手机」功能的 APK）

> 云打包为什么不行：HBuilderX 的「原生App-云打包」只认**插件市场买过**的原生插件，
> 本地插件 `GuyuGuard` 没在市场绑定你的 AppID，服务器就报
> 「未在插件市场购买或申请试用」。这不是插件坏了，是云打包这条路本身不收本地插件。
>
> 要让「📲 真手机」真的能看屏幕时间、截屏、锁软件、读通知，只有两条路：
> **① 离线打包（本文，免费、不用审核）** ② 把插件发布到市场再 0 元「购买」绑定 AppID。
>
> 只是想先要个能用的谷雨、不要真手机功能的话，别看这篇——
> 直接把 `manifest.json` 里 `nativePlugins` 那段删掉，照常云打包就行。

离线打包就是：不走 DCloud 云端，自己用 **Android Studio** 把谷雨的网页 + 谷雨守护
的 `GuyuGuard.aar` 一起编成 APK。整件事在**你自己的电脑**上做，我这边代替不了
（要登录你的 DCloud 账号下 SDK、要装 Android Studio）。

---

## 零、先准备这些

| 要什么 | 哪来 | 说明 |
|---|---|---|
| DCloud 账号 | 你已经有（HBuilderX 登录的那个） | 下离线 SDK 要登录 |
| **Android 离线打包 SDK** | https://nativesupport.dcloud.net.cn/AppDocs/download/android | 下「最新Android平台SDK」，解压 |
| Android Studio | https://developer.android.com/studio | 第一次装会自动下 SDK/Gradle，耐心等 |
| JDK 17 | Android Studio 自带 | 不用单独装 |
| 谷雨守护插件 | 本仓库 `安卓插件/nativeplugins/GuyuGuard/` | 里面的 `android/GuyuGuard.aar` 是成品 |

> 离线 SDK 的版本会变，下面凡是写到「某个目录/某个文件」的地方，**以你下到的
> SDK 里 `说明.txt` / 官方文档为准**；谷雨守护专属的部分（哪个 aar、要注册哪两个
> 服务、要哪些权限）我在本文写死了，照抄即可。

## 一、把 SDK 里的示例工程导进 Android Studio

1. 解压离线 SDK，里面有个示例工程目录（一般叫 `HBuilder-Integrate-AS` 之类）。
2. Android Studio → **Open**，选这个目录，等它把 Gradle 跑完（第一次很慢）。
3. 先原样编一遍（▶ Run），能装到手机上、能打开示例页面，说明环境没问题，再往下改。

> 这一步要是卡在下 Gradle / SDK，多半是网络。挂个梯子，或在
> `File → Settings → Build → Gradle` 里换国内镜像。

---

## 二、换成谷雨的网页

离线 SDK 的 app 模块里有个放前端资源的地方，通常是
`app/src/main/assets/apps/<你的AppID>/www/`。

1. 打开 HBuilderX 里谷雨项目的 `manifest.json`，记下 **AppID**（`__UNI__` 或
   `H5A…` 开头那串），SDK 里的目录名要和它一致。
2. 把谷雨这些拷进那个 `www/` 里（**和云打包时拷的东西一样**）：

   ```
   index.html
   style.css   及其它 .css
   js/           （整个文件夹，含 js/vendor/）
   icons/  img/  media/  启动页/   等页面会用到的资源
   pwa-manifest.json   （可选，APK 用不到也无害）
   ```

   **不要拷** `manifest.json`（那是 PWA 的）、`_开发测试/`、`桌面版/`、
   `_tmp/`、各种 `*_备份_*`。
3. 入口页保持 `index.html`。SDK 的 `dcloud_control.xml` 里 `app` 的 `appid` 要填你
   的 AppID，`entry`/首页指向这个 www。（具体字段名看 SDK 文档，别手改错。）

## 三、把谷雨守护的 aar 装进去（关键一步）

### 3.1 放 aar

把 `安卓插件/nativeplugins/GuyuGuard/android/GuyuGuard.aar` 拷到 app 模块的
`libs/` 目录里，然后在 app 的 `build.gradle` 的 `dependencies` 里加一行：

```gradle
dependencies {
    // …SDK 原有的那些别动…
    implementation fileTree(dir: 'libs', include: ['*.aar', '*.jar'])
    // 如果上面这行 SDK 里已经有了，就不用重复加
}
```

### 3.2 注册两个服务 + 权限

谷雨守护要往 app 的 `AndroidManifest.xml` 里加东西。**照抄**下面这些（源出
`安卓插件/GuyuGuard-源码与构建/aar/AndroidManifest.xml`，已核对）：

`<manifest>` 里（和 SDK 原有权限并列，重复的留一份即可）：

```xml
<uses-permission android:name="android.permission.PACKAGE_USAGE_STATS" tools:ignore="ProtectedPermissions" />
<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES" />
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
<uses-permission android:name="android.permission.WRITE_SETTINGS" tools:ignore="ProtectedPermissions" />
<uses-permission android:name="android.permission.ACCESS_NOTIFICATION_POLICY" />
<uses-permission android:name="android.permission.SET_WALLPAPER" />
<uses-permission android:name="com.android.alarm.permission.SET_ALARM" />
<uses-permission android:name="android.permission.VIBRATE" />
<uses-permission android:name="android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS" />
```

（`<manifest>` 根标签记得有 `xmlns:tools="http://schemas.android.com/tools"`，
上面 `tools:ignore` 才不报错。）

`<application>…</application>` 里：

```xml
<!-- 无障碍：挡被锁的软件、读屏、截屏 -->
<service android:name="com.guyu.guard.GuardAccess"
    android:label="谷雨守护" android:exported="true"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
    <intent-filter><action android:name="android.accessibilityservice.AccessibilityService" /></intent-filter>
    <meta-data android:name="android.accessibilityservice" android:resource="@xml/guyu_guard_access" />
</service>

<!-- 通知监听：读别的软件的通知 -->
<service android:name="com.guyu.guard.GuardNotify"
    android:label="谷雨" android:exported="true"
    android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE">
    <intent-filter><action android:name="android.service.notification.NotificationListenerService" /></intent-filter>
</service>
```

### 3.3 补两个资源文件

上面 `GuardAccess` 用到了 `@xml/guyu_guard_access` 和一段文字，aar 里带了，但保险起见
在 app 模块里也放一份（从 `安卓插件/GuyuGuard-源码与构建/aar/res/` 拷）：

- `app/src/main/res/xml/guyu_guard_access.xml`
- `app/src/main/res/values/` 里那段 `guyu_guard_desc` 文案（并进你的 `strings.xml`）

### 3.4 让 5+ 运行时认得这个原生模块

谷雨网页是用 `plus.android.importClass('com.guyu.guard.Guard')` 直接调 Java 的，
这种**不用**在 `dcloud_properties.xml` 里注册模块，`importClass` 能直接拿到类——
只要 aar 进了包、类名没写错就行。
（如果你哪天改成用 `uni.requireNativePlugin('GuyuGuard')` 调，那才需要去
`dcloud_properties.xml` 里按 SDK 文档注册 `GuardModule`。目前谷雨不用。）

## 四、编出 APK

Android Studio → **Build → Build Bundle(s)/APK(s) → Build APK(s)**。
编完点 `locate` 就能找到 `app/build/outputs/apk/debug/app-debug.apk`。

- 这是**调试版、没签名**。装的时候手机要允许「安装未知来源应用」。
- 想要正式签名版（能长期用、能给别人装）：**Build → Generate Signed Bundle / APK**，
  第一次让你 `Create new…` 生成一个 keystore，口令和那个 `.jks` 文件**自己存好**，
  以后更新 APK 必须用同一个，丢了就只能换包名重装。

## 五、⭐ 打包完之后怎么做（你问的这步）

APK 只是第一步，**真手机功能要手动授权才会亮**。按顺序来：

### 5.1 装上

把 `app-debug.apk` 传到手机，点开安装，允许「未知来源」。
装完先打开谷雨，确认聊天、AI 这些本体功能正常（白屏的话看第六节）。

### 5.2 开 5 个权限（缺一个，对应功能就用不了）

进**手机系统设置**里开，不是在谷雨里：

| 要开的 | 去哪开 | 不开会怎样 |
|---|---|---|
| **无障碍** → 找到「谷雨守护」打开 | 设置 → 无障碍 / 辅助功能 | 锁软件、读屏、截屏全废 |
| **使用情况访问 / 有权查看使用情况** | 设置 → 应用 → 特殊权限 → 使用情况访问 | 看不到屏幕使用时间、在用什么 |
| **通知使用权 / 读取通知** → 开「谷雨」 | 设置 → 通知 → 通知使用权 | TA 读不到别的软件的通知 |
| **显示在其他应用上层 / 悬浮窗** | 设置 → 应用 → 谷雨 → 权限 | 把你从被锁软件拉回来会失效 |
| **修改系统设置** | 设置 → 应用 → 谷雨 → 权限 | 换壁纸、手电、震动可能没反应 |

> 不同牌子手机（OPPO/小米/华为…）菜单名字不一样，搜「无障碍」「使用情况」
> 「通知使用权」「悬浮窗」这几个词就能找到。再把谷雨加进**电池 → 不受限制 /
> 允许后台运行**，不然息屏一会儿 TA 就被系统杀了，主动消息收不到。

### 5.3 在谷雨里自检（唯一准的验证）

谷雨里进 **📲 真手机 → 设置**，看最上面：

- 显示 **「✓ 谷雨守护 1.0.0 装好了」** → aar 进包成功，功能可用。
- 显示没装好 / 调不到 → aar 没编进去，或类名不对，回第三节检查
  `GuyuGuard.aar` 在不在 `libs`、`build.gradle` 加没加那行依赖。

然后逐个试：屏幕使用时间、截屏、锁一个软件。某项不灵，基本就是 5.2 里对应那个
权限没开。

## 六、出问题怎么查

- **白屏**：多半是前端资源没拷全或入口页不对。谷雨启动失败会自己弹白底报错面板，
  写明哪个文件第几行，截图就能定位。连面板都不弹 = WebView 没加载到 `index.html`，
  回第二节检查 www 目录和入口页。
- **「谷雨守护没装好」**：aar 没进包。确认 `GuyuGuard.aar` 在 `app/libs/`，
  `build.gradle` 里有 `implementation fileTree(... '*.aar' ...)`，然后
  **Build → Clean Project** 再重新 Build。
- **功能点了没反应**：对着 5.2 的表一个个权限查，基本都是漏开了某个。
- **编译报「找不到符号 / duplicate class」**：SDK 自带的依赖和你加的撞了，
  把重复的那行依赖删掉一份。

## 七、不做成插件，把源码直接放进项目（推荐）

「做成插件」和「做进项目」对这几个功能来说，差别只在 **native 代码放哪**，
不是能不能用纯网页实现——屏幕使用时间、截屏、锁软件、读通知都是安卓系统级能力，
网页里没有对应接口，所以无论如何都得有一层 Java。插件只是把这层 Java 预编译成
`.aar` 的一种打包方式。离线打包里你可以**完全不用 aar、不用 `nativePlugins`**，
把源码当成 app 自己的一部分：

1. 把这三个文件从 `安卓插件/GuyuGuard-源码与构建/src/com/guyu/guard/` 拷到
   app 模块的 `app/src/main/java/com/guyu/guard/` 下：
   `Guard.java`、`GuardAccess.java`、`GuardNotify.java`。
   > - `GuardModule.java` **不要拷**——它是给 uni-app 用的空壳（`extends UniModule`），
   >   谷雨用 `importClass` 直接调 `Guard`，不需要它；5+ 离线 SDK 里也多半没有
   >   那个 `UniModule` 基类，拷了反而编不过。
   > - `stubs/` 那些**也不要拷**——它们只是让 `build.sh` 在没装安卓 SDK 时能骗过
   >   编译器，app 模块里有真正的 Android SDK，用系统真货。
2. AndroidManifest 的两个 `<service>` + 那串权限，和第三节一模一样，照抄。
3. `res/xml/guyu_guard_access.xml` 和那段文案，照第 3.3 节放。
4. **不用**注册任何插件、不用 `nativePlugins`。谷雨网页里
   `plus.android.importClass('com.guyu.guard.Guard')` 会直接找到编进 app 的这个类。

这样 `manifest.json` 里根本没有 `nativePlugins` 这段，「未购买」报错自然就没了。
用第五节一样的方法装、授权、自检即可。

> ⚠️ 这条路**还是只能离线打包**。云打包只编 JS/HTML/CSS，你丢进去的 `.java` 它不编；
> 往 5+App 塞 native 代码的唯一通道就是原生插件，而插件就会触发市场校验。
> 也就是说：**能不能云打包取决于「要不要 native 能力」，不取决于「做不做成插件」。**
> 真手机这些功能是 native 的，就绕不开离线打包。

## 八、两条路对比（拿不定主意看这）

| | 离线打包（本文） | 发布到插件市场再云打包 |
|---|---|---|
| 花钱 | 免费 | 免费（0 元插件） |
| 要不要审核 | 不用 | 要，等 DCloud 审 |
| 难度 | 装 Android Studio，步骤多 | 填表、提交包名，绑 AppID |
| 以后更新谷雨 | 重新 Build 一次 | HBuilderX 里照常云打包 |
| 适合 | 只给自己/少数人用，想一次搞定 | 以后要经常云打包更新 |

自己一个人用、想彻底摆脱「未购买」报错 → 离线打包。
以后还想用 HBuilderX 一键云打包 → 走插件市场那条。
