MCP 真实操作：上传与手机验收说明
整理日期：2026-11-24

一、交付范围与版本
网页版本：316；Android：1.62（code 162）；谷雨守护：1.3.0。
本次完成 Android 美团操作原型：能力自检、任务记录、排队与取消、页面校验、搜索店铺、选商品及规格、购物车核验、结算核对、人工接管、用户确认提交、订单结果核验。
还没有实现其他购物平台或桌面软件的通用操作，也没有证明真实美团所有版本都可用。当前适配规则以受控页面样例验证，必须在实际手机采样验收；识别不到字段时应停止，不能删除校验来强行点击。

二、已完成的本地验证
详见同目录《MCP真实操作-自检结果.json》：36/36 项脚本与编译检查通过。
包括 Java 编译与三个 Android 占位接口测试、MCP 协议及任务状态、排队去重、取消超时、页面指纹、人工接管、店铺/商品/结算/订单解析、网页交互、隐私与结果状态、APK 下载后安装恢复、离线启动、缓存清单、隔离目录 Cloud 全量包构建。
这是脚本数量，部分脚本会重复导入单元用例，不能累加其中断言数作为独立用例总数。
原生插件 AAR 已构建；检查不包含 Android/DCloud 接口占位类或测试类。占位编译通过不代表已通过真实 Android SDK 编译和设备运行验证。
没有运行：签名 APK 完整构建、GitHub Actions、实际 Cloud 部署、手机覆盖安装、真实应用页面操作、真实订单及付款；Cloud 差量更新分支也没有在本轮运行。

三、上传与生成测试 APK
1. 先备份手机数据，保留目前可用的安装包。不要为了测试直接卸载应用。
2. 所有新增 JS、测试、Java、文档、AAR 和工作流都需要一起上传。本地尚未提交或推送，未部署。
3. 现有“上传到GitHub.bat”会检查 android-build/www-manifest.json 的版本改动；当前已是 1.62/162，会复用这一版，不需要手动再加一次版本。脚本会提交工作区其他改动，上传前请检查范围。
4. APK 工作流现在默认仅生成 guyu-apk 测试产物，不自动替换 apk Release。检查 Actions 是否真正产出 APK，不能只看任务绿色；缺少 sdk Release 时会跳过。
5. 仓库必须已配置离线 SDK 和原安装包所用的签名证书。缺少 KEYSTORE_B64 / KEYSTORE_PASS 会终止打包；其他签名参数也须与既有配置一致。使用不同证书无法覆盖安装。
6. 从 Actions 的 guyu-apk 产物取得签名 APK，在自己的测试手机覆盖安装。只有网页/WGT 更新无法增加原生接口，必须先安装含新版谷雨守护的 APK。
7. 如使用 HBuilderX 云打包，确认工程实际集成了本次 nativeplugins/GuyuGuard 及其 AAR，并使用同一证书。源码在仓库里不等于已装入手机。
8. 真机验收后，如需更新公开下载，可手动运行“打包 APK”并勾选 publish。默认不勾选。网页上传是否更新线上 Cloud，仍由项目原有部署流程决定。

四、建议的手机验收顺序
1. 确认应用版本与网页版本；开启所需无障碍、读屏和应用可见性权限，运行 MCP 手机能力自检。pageSafety、orderConfirmation、orderReceipt 必须可用。旧插件或浏览器环境应明确拒绝受保护写操作。
2. 先只测试读屏、搜索、选店：检查当前包名、店名、候选内容是否准确。遇到验证码、登录、地址、规格不明或页面不匹配，确认任务停下并提示人工处理。
3. 测试单个商品和规格、数量及购物车：核对每次只增加预期数量；重复请求不能重复加购；取消、超时、切换页面后不能继续执行旧任务。
4. 在结算界面核对商品、费用、总价、地址和手机号。本地核对界面可显示完整信息，专用结算工具给模型的结果应脱敏。现有通用读屏工具仍可能看到敏感内容，不代表全项目所有工具都已脱敏。
5. 测试人工接管与恢复：接管后刷新应用仍保持暂停；只有用户主动确认、重新读取当前页面才恢复；原任务不能自动重放。
6. 优先测试取消原生提交确认：未勾选、过期、页面变化、缺字段、免密/自动扣款或付款方式不明时，应拒绝提交。模型没有提交订单工具，提交必须由本地用户操作并经原生弹窗再次确认。
7. 是否实际创建订单由测试者决定。仅在前述步骤通过、付款方式明确且能接受费用时再测试。系统不会自动付款；不要依赖测试脚本替你判断实际订单风险。
8. 提交后应显示“结果未核验”，而非直接宣布购买成功。打开实际订单详情，核对订单号、时间、店铺、商品与金额；用户确认归属后才能解除此次提交锁。待支付、支付失败、取消、退款、配送与已支付要区分。
9. 提交后断网、退出或没有看到结果时，不能自动重试下单。先在平台订单列表人工查明。无法可靠匹配订单时保持锁定，人工在平台处理。

五、原 APK 下载完不能安装的回归验收
修复包含：保留下载文件、重新进入前台安装、授权未知来源安装后重试、下载完成后再次点击安装，不以安装成功回调作为唯一依据。
先验证当前 APK 覆盖安装和证书一致。完整更新回归需要后续一个版本号更高、证书相同的 APK；不要降级或卸载来凑测试条件。
依次验证：下载完成立即安装、返回前台安装、拒绝权限再授权重试、安装弹窗取消后重试、断网后复用已下载文件、文件无效时给出失败提示。Android 普通应用无法保证静默安装，系统确认界面仍由用户操作。

六、本地复跑命令（在项目根目录）
node _开发测试/mcp-final-checks.mjs
powershell -ExecutionPolicy Bypass -File tools/build_guard.ps1
需要 Node、项目现有 Playwright/Edge 测试依赖、Python，以及 JDK 17 或更高版本。未安装的依赖请按现有开发测试说明配置。
测试报告会被复跑结果覆盖。原生构建会更新 AAR 和源码副本，不会构建完整签名 APK。

七、剩余风险及反馈
真实美团界面可能与样例完全不同，缺少匹配字段时会停止；需根据实际节点做下一轮适配。
排队主要约束同一应用实例，不能视为跨设备或服务端幂等保障。已发出的外部动作无法靠取消撤回。
订单结果必须人工确认归属；不确定时保持未核验，不能将普通页面变化当作业务成功。
反馈时记录手机型号、Android/美团版本、失败步骤、自检结果和错误原文，遮盖姓名、电话、地址及完整订单号。不要反馈证书、密钥或支付凭据。
