# 酒馆兼容层：现在接到哪一步了

## 一、楼层：跟酒馆一致

### 楼层号从 0 开始

酒馆里一段对话就是数组 `chat[]`，**下标就是楼层号（message_id）**：

```
message_id 0 ← 开场白（它的 swipes 就是角色卡那一串候选开场白）
message_id 1 ← 用户说的话
message_id 2 ← AI 的回复（它的 swipes 是重 roll 出来的几个版本）
```

谷雨原来显示 `#1楼` 起，现在改成 `#0楼` 起。不是为了好看——
**角色卡调 `setChatMessages([{message_id:N}])` 说的就是这个号**，显示成 1 起会差一层。

### 字段是同一份数据，只是名字不同

| 酒馆 | 谷雨 | |
|---|---|---|
| `message_id` | 数组下标 | |
| `role` | `role` | 谷雨 `'ai'` ↔ 酒馆 `'assistant'` |
| `message` | `text` | |
| `swipe_id` | `currentSwipe` | |
| `swipes` | `swipes` | |
| `is_hidden` | `hidden` | 谷雨的「隐藏楼层·不进 prompt」 |
| `data` | `data` | 楼层变量，新增 |

**谷雨内部字段名没改**，翻译只在兼容层这一层。

### 卡片现在能对楼层做的

```js
getChatMessages('0-{{lastMessageId}}')     getChatMessages(-1)        // 负数=深度
getChatMessages('0-3', {role:'user'})      getChatMessages(2, {include_swipes:true})
getLastMessageId()
setChatMessages([{message_id:1, message:'新正文'}])      // 改任意一楼
setChatMessages([{message_id:2, swipe_id:1}])            // 切任意一楼的版本
setChatMessages([{message_id:0, swipe_id:3}])            // 第0楼＝换开场白（走完整后处理链）
setChatMessages([{message_id:0, is_hidden:true}])
createChatMessages([...], {insert_before:1})   deleteChatMessages([3])   // 删会先弹确认
```

## 二、你批准的三条，都做了

**① `{{getvar}}` 支持点号路径**

```js
// 卡片写
insertOrAssignVariables({神乐光: {好感度: 5, 认知度: 0}})
// 你的宏现在能读到
{{getvar::神乐光.好感度}}   → 5
{{getvar::神乐光}}          → {"好感度":5,"认知度":0}   （以前是 [object Object]）
```

`{{setvar::a.b::x}}` / `{{addvar}}` 也跟着走路径了。**没有点号的老写法完全不受影响**——
`split('.')` 出来就一段，行为跟以前一模一样。

**② 楼层变量「读合并、写分开」**

`getVariables({type:'message'})` 返回 **MVU 快照（AI 写的状态树）叠上 `turn.data`（卡片写的）**，
所以状态栏卡片能直接读到疲劳度、好感度这些真实数值。
写只写进 `turn.data`，**绝不碰 MVU 树**——卡片改不坏 AI 的状态。

**③ 切换续写会话发 `CHAT_CHANGED`**，卡片能借此重置自己的状态。

## 四、这三个也接上了

### 模型列表 → 设置页那个「🔄 拉取模型」

`getModelList()` 用的**就是设置页拉取按钮同一份逻辑**。原来那段 fetch+解析在主API/副API/向量
三个按钮里各抄了一遍，现在抽成 `fetchModelListFrom(url, key)`，三个按钮和卡片共用。
所以卡片看到的模型列表跟你自己点拉取看到的完全一致，不会出现两边不一样的情况。

传 `'sub'` 拿副 API 的列表。

### 扩展安装 → 谷雨的插件系统

酒馆的"扩展"＝从 git 装一份前端代码。谷雨对应的就是**插件**（prompt / action / macro / script 四类）。
`installExtension` 现在接到 `plugins` 上，装完出现在「设置 → 插件」里，你随时能关能删。

**git 地址会真的下载。** 谷雨部署在本地，装什么都是自己的机器，所以不再一刀切拒绝。
三种写法都支持：

- 直接给 `.json` —— 谷雨插件导出文件，原样用
- 直接给 `.js` —— 当成 script 类插件的代码
- 给 **GitHub 仓库地址** —— 自动转成 raw 地址，`main`/`master` 两个分支 ×
  `谷雨插件.json` / `guyu-plugin.json` / `plugin.json` / `plugins.json` / `index.js` / `script.js`
  挨个试，找到哪个算哪个

**但下下来之后仍然先给你看清楚再装**：弹框把名字、类型、说明一条条列出来；
`script` 类额外再警告一次（这类插件在主页面跑真代码，权限比角色卡自己高得多）。
你不点同意就什么都不会发生。这一层留着不是防你，是防"卡片趁你不注意装了个东西"。

配套的 `uninstallExtension`（也要确认）/ `isInstalledExtension` / `getExtensionInstallationInfo` 都有。

### 脚本按钮 → 续写页上方的按钮栏（语义按你说的改了）

酒馆把这类按钮挂在**脚本库的抽屉**里；谷雨改成放在**续写操作区上方**（`#ssCardButtons`）——
卡片本来就在这个页面里，按钮离它近才用得顺手。

行为保持酒馆的：点一下把事件发回给注册它的那张卡，事件名用**跟酒馆一模一样的算法**
（`getButtonEvent(名字)` → `<script_id>_<名字>_button_clicked`），卡片那边
`eventOn(getButtonEvent('查看手账'), fn)` 直接就能收到。`script_id` 两边都取这张卡的角色 id，保证算出同一个值。

注册信息**存在会话上**，所以卡片重渲染、iframe 重建都不会把按钮弄丢。传空数组就撤掉。

`updateScriptButtonsWith(id, fn)` 那个"传函数进去改"的接口也有——函数没法跨 iframe 传，
所以在卡片本地先算好再整体替换，对卡片来说行为一样。

## 五、音频播放（新加的）

谷雨原来只有 TTS 朗读，没有音频播放器。现在补了一个真的：

- `playAudio({url, volume, loop})` / `pauseAudio()` / `getCurrentAudio()` /
  `getAudioSettings()` / `setAudioSettings()` / `getAudioList()` / `replaceAudioList()`
- 右下角会出现一个**小控制条**（播放/暂停、音量滑块、✕ 关闭）。
  这个是我自己加的，酒馆没有——卡片自己放的 BGM 要是没地方关掉，你就只能刷新整个页面。
- 浏览器拦下自动播放时（还没交互就 play 是被禁止的）不会静默失败，

## 六、开场白美化：直接显示

现在的角色卡很多会给开场白配一条正则（叫「开场白跳转」「开场主页」这类），
把 `<greetings>...</greetings>` 或者【开场白】这种标记整个换成**一整页做好的 HTML**——
一排可点的场景卡片，点一下就用那条开场白开局。

以前谷雨的挑选框只按纯文本列，等于把作者做好的那一页完全浪费了。现在：

- **有美化版的直接显示美化版**，走跟楼层完全同一条渲染链路（正则 → iframe 隔离），
  所以那一页里的 `setChatMessages` 照样能用，点一下就开局，开完弹窗自动关掉
- **勾了多个角色**时，上面多一排角色按钮，可以切着看每个角色的开场白；
  有美化版的角色标了 🎨 并且排在前面
- 切到没有美化版的角色，自动回落成原来的纯文本候选列表
- 两种视图之间随时能手动切（「📄 看纯文本列表」/「🎨 看美化开场白」）——
  美化那页偶尔会漏掉几个候选，或者你就是想看原文，留个退路

顺手修掉一个真 bug：**这段续写还一楼都没有**的时候，
卡片调 `setChatMessages([{message_id:0, swipe_id:N}])` 原来会因为"第 0 楼不存在"被跳过。
而这恰恰是最常见的场景——你点开挑选框、美化开场白就摆在眼前、点一个场景要开局。
现在按语义走：第 0 楼 ＝ 开场白，没有就创建。

## 七、用户人设（persona）

`getPersonaIds` 是酒馆里"**你自己**的身份档案"的 id 列表——名字、头像、自我描述，
可以存好几份随时切（"本体""马甲小号"）。卡片拿它来称呼你、显示你的头像，
或者按不同人设走不同剧情分支。

这个谷雨也有：用户资料里那份「人设」列表（`userPersonas`，每份是一整份 `currentUser` 快照）。
现在接上了：

| 酒馆 | 谷雨 |
|---|---|
| `getPersonaIds()` | `userPersonas` 的 id 列表 |
| `getPersonaNames()` | 每份人设里的名字 |
| `getPersona(id)` \| `'current'` | 那份快照，字段翻译成酒馆的 Persona 形状 |
| `getCurrentPersonaId()` | 见下面那条注意 |
| `getPersonaAvatarPath(id)` | 那份人设的头像（base64） |
| `switchPersona(id)`（谷雨扩的） | `switchToPersona`，**会先问你一句**——这是改你的用户资料 |

两处结构差异：

- 酒馆用**头像文件名**当 persona 的唯一 id（历史包袱），谷雨用自己生成的 `persona_xxx`。
  对卡片来说都只是个不透明字符串，不影响使用。
- 谷雨**没有单独记"当前是哪个人设"**——切换时是把快照整体覆盖进 `currentUser` 的。
  所以 `getCurrentPersonaId` 是反推的：先看人设下拉框选的是谁，没有就拿名字+账号去比对。
  你要是手改过用户资料让它跟任何一份人设都对不上，这里会返回 `null`——这是诚实的答案，
  不硬猜一个。

## 八、161 个接口，接上 113 个，54 个兜底

酒馆助手总共 **161 个接口**。我先前说"没有留空值的接口了"是错的——
真实情况是剩下那些**根本没定义**，卡片一调就是 `xxx is not a function`，
整个脚本当场断在那里、后面的界面全废。这比返回个空值糟得多。

已经把 ST 的接口名单整个列进 `js/03`，凡是没真接上的，一律装一个**安全空实现**：
按名字猜合理返回值（`Names`/`List`/`Entries` 结尾 → `[]`，`is*` → `false`，
`create/delete/replace/update/set/...` → resolved Promise，其余 `get*` → `{}`），
并在控制台留一行"这张卡片调用了 xxx()，谷雨没有对应功能，已安全跳过"。
每个空实现带 `__gySafeStub` 标记，调试时一眼能看出是兜底的还是真接上的。

### 那 54 个兜底的，分四类

**① 谷雨的数据模型不一样，硬接会对出错误数据（22 个）**

`createLorebook` `deleteLorebook` `getChatLorebook` `getOrCreateChatLorebook`
`setChatLorebook` `getChatWorldbookName` `getOrCreateChatWorldbook`
`rebindCharWorldbooks` `rebindChatWorldbook` `rebindGlobalWorldbooks`
`setCurrentCharLorebooks` `getLorebookSettings` `setLorebookSettings`
`replaceLorebookEntries` `deleteLorebookEntries` `updateLorebookEntriesWith`
`createOrReplaceWorldbook` …

酒馆的世界书是**"一本书里有很多条目"**，而且分"角色书/聊天书/全局书"三种绑定关系；
谷雨是**"一本＝一条"**、靠关键词和 `isGlobal` 触发。读取那几个我做了形状翻译（够用），
但"给这个聊天单独建一本书""重新绑定角色的主书"这类**在谷雨里没有对应概念**——
硬造一个出来只会让你在世界书页面看到一堆莫名其妙的条目。

**② 需要"传函数进去"或"传文件进去"，跨 iframe 做不到（10 个）**

`updateCharacterWith` `updatePresetWith` `updatePersonaWith` `updateScriptTreesWith`
`updateTavernRegexesWith` `updateLorebookEntriesWith` `importRawCharacter`
`importRawChat` `importRawPreset` `importRawTavernRegex` `importRawWorldbook`

函数和文件句柄都没法 `postMessage`。**能取巧的我已经取巧了**——
`updateVariablesWith` / `updateWorldbookWith` / `updateScriptButtonsWith`
改成"在卡片本地先算好、再整体替换"，对卡片来说行为一样。
剩下这些的数据太大或结构太深，本地算完再传回去不划算，而且 import 那一批本质是
"让卡片往你库里塞角色/预设/正则"——这个我不想让卡片绕过导入界面偷偷做。

**③ 酒馆自己的内部机制，谷雨没有这一层（14 个）**

`getScriptTrees` `replaceScriptTrees` `replaceScriptInfo` `getProxyPresetNames`
`isPresetNormalPrompt` `isPresetSystemPrompt` `isPresetPlaceholderPrompt`
`registerMacroLike` `unregisterMacroLike` `registerVariableSchema`
`reinstallExtension` `updateExtension` `appendInexistentScriptButtons`
`getAllEnabledScriptButtons` `rotateChatMessages` `retrieveDisplayedMessage`

脚本树、代理预设、预设提示词的内部分类、宏注册表、变量 schema——
这些是酒馆的内部实现细节，谷雨的架构里没有对应的东西。

**④ 增删角色/预设/人设的"批量写"变体（8 个）**

`createCharacter` `deleteCharacter` `replaceCharacter` `createOrReplaceCharacter`
`createPreset` `replacePreset` `setPreset` `createOrReplacePreset`
`createOrReplacePersona` `replacePersona`

单数形式我接了能接的（`createPersona` / `deletePersona` / `deletePreset` /
`renamePreset` 都真的能用，且**都会先弹框问你**）。
这些批量/覆盖变体没接，是因为"让角色卡直接覆盖你的角色库和预设库"风险和收益不成正比——
真需要哪个跟我说，单独做，照样加确认。

> 判断标准很简单：**能对上谷雨真实数据的就真接**，
> **对不上的宁可返回空值也不假装**——假装对上了、悄悄写进错误的地方，比不做更难查。

## 九、事件

谷雨真实会发的：

| 事件 | 什么时候 |
|---|---|
| `message_sent` / `generation_started` | 点发送、用户那楼入库时 |
| `message_received` / `generation_ended` | AI 回复落地、完整渲染之后 |
| `message_updated` | 编辑楼层、隐藏/取消隐藏、卡片调 `setChatMessages` 改了内容 |
| `message_swiped` | 切版本（点◀▶ 或卡片调 `setChatMessages` 切 swipe） |
| `message_deleted` | 删楼层 |
| `chat_id_changed` | 切换续写会话 |
| `stream_token_received` | 卡片 `generate({should_stream:true})` 期间的增量 |
| `generation_stopped` | `/abort` 或 `stopAllGeneration` |

监听谷雨不发的事件不会报错，只是永远不触发。

**跟酒馆的一个结构差异**：酒馆的 iframe 跟主程序同源，事件能传对象引用；
谷雨这边是 `postMessage`，**只能传能 JSON 序列化的**，所以发的是 `message_id`，
卡片拿到再 `getChatMessages(id)` 去取——等价且更稳。

## 十、同步 vs 异步（唯一一处跟酒馆语义不同的地方）

卡片调 `getChatMessages` / `getVariables` 是**同步**的（不 await），跨 iframe 没法同步问主页面，
所以这些数据在建 iframe 时就随快照塞进去，楼层一变主页面**主动推新快照**过来。

因此**同步读的接口**（快照供数据）：`getChatMessages`、`getVariables`、`getLastMessageId`、
`getCharacterNames`、`getWorldbookNames`、`getPresetNames`、`getCharAvatarPath`、`substitudeMacros`(简版)。

**异步的**（postMessage 往返，酒馆那边这些本来也是异步的）：`setChatMessages`、`generate`、
`triggerSlash`、`getWorldbook`、`formatAsTavernRegexedString`、`substitudeMacros`(完整版)、`injectPrompts`……

一个要注意的：**iframe 里的 `substitudeMacros` 是简版**（只认 `{{char}}` `{{user}}` `{{lastMessageId}}`），
因为 `{{setvar}}` 这种带副作用的宏必须在主页面跑。要完整版的话卡片得 `await TavernHelper.substitudeMacros(...)`——
返回 Promise 而不是字符串。这是唯一一处跟酒馆行为不同、可能让卡片踩坑的地方，先记在这。

### 快照有上限

开场白那楼永远带上 + 最近 40 楼 + 总字数 20 万封顶；头像超过 300KB 不塞。
不够就调 `js/17` 顶上的 `GY_SNAPSHOT_MAX_FLOORS` / `GY_SNAPSHOT_MAX_CHARS` / `GY_SNAPSHOT_MAX_AVATAR`。
