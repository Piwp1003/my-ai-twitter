谷雨 · 主 API / 副 API 谁在干什么
（v107 · 已按方案 A 落地）


════════════════════════════════
一句话
════════════════════════════════

你会**逐字读**的内容走主 API（好模型），
你多半只是扫一眼的内容走副 API（便宜模型）。

副 API 没填全（地址+密钥+模型三样）的时候，全部退回主 API，一切照常。


════════════════════════════════
代码里怎么取的
════════════════════════════════

    getApiMain()          主的优先；主的没配全 → 退到副的
    getApiConfig(true)    副的优先；副的没配全 → 退到主的
    getApiConfig(false)   只用主的，不退

以前全项目 60 多处取 API，56 处传的都是 true——
副 API 一填就接管一切，主 API 只剩四件事。v107 把「重要」的那批改成了 getApiMain()。
