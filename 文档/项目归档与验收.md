## 风险和修改注意事项

- 前端脚本按顺序加载，多处共享全局状态。改模块需核对 index.html 的加载顺序、service-worker.js 的缓存清单、打包文件及旧缓存升级。改原生插件需要相应 APK；区分网页版本、WGT 和 APK 版本。
- 数据和授权按用户、平台账号、会话及角色分开。模型、云同步、插件或外部代理收到的数据范围需要可解释；撤权、切号和异步返回同时发生时应重新校验。日志与备份避免写入令牌或支付详情。
- 导入角色卡、插件、正则和自定义 HTML 可影响渲染或执行脚本。修改兼容层需同时验证现有卡片和不可信输入。参考[历史安全报告](安全检查报告.md)，其中时效性结论需复核。
- QQ/微信第三方客户端适配可能受客户端更新、离线、账号限制影响。普通用户无电脑的可用性、服务托管成本和第三方许可需在公开分发前确认。
- 外部购物中，工具返回、页面跳转、创建订单、支付成功是不同的证据。超时后的写操作不能盲目重放；实测时核对商品、数量、总额、实际订单及手动付款边界。
- 分发遵循根目录 LICENSE 和第三方许可。现有 GitHub 构建与 Cloud 部署是独立环节；安装/覆盖和真实账号收发应记录环境，不能用模拟结果替代。
