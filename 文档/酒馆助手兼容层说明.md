# 「环境未配置酒馆助手」是怎么回事，现在补上了

## 为什么突然冒出这个提示

这是上一个修复带出来的。

之前谷雨把角色卡的 HTML 组件用 `innerHTML` 塞进页面，**卡片自带的 `<script>` 根本不会执行**，
所以卡片对酒馆接口的依赖一直是隐形的——你看不到提示，是因为卡片压根没跑起来。

现在卡片改成在 iframe 里正常运行，脚本一跑就开始找酒馆助手的接口，找不到就照它自己写的
提示语弹出来：「环境未配置酒馆助手」「酒馆助手API未就绪」。

**换句话说：这个提示是卡片终于活过来的证据，不是新坏了。**

## 卡片到底要什么

我把你给的 14 张卡的脚本挨个扫了一遍，实际用到的接口就四个，而且高度集中：

| 接口 | 出现次数 | 卡片拿它干嘛 |
|---|---|---|
| `setChatMessages([{message_id:0, swipe_id:N}])` | 33 | **绝对主力**：把开场换成第 N 个开场白 |
| `triggerSlash('/echo ...')` | 25 | 基本都是弹个提示条 |
| `getChatMessages('0', {include_swipes:true})` | 4 | 读开场白列表，好把菜单画出来 |
| `getCurrentMessageId()` | 2 | — |

看懂第一条是关键：**「第 0 条消息的 swipes」就是角色卡里那一串候选开场白**。
所以那 33 处调用翻译成人话都是同一件事——「把开场切换成第 N 个开场白」。

而这件事谷雨**本来就有**（开场白挑选框）。以前只能从谷雨自己的按钮进，
现在让卡片里那一整页漂亮的场景菜单也能触发。

## 加了什么

**新增 `js\17-tavern-bridge.js`**（主页面这一侧）：

- `gyTavernContextFor(charId)` —— 准备快照。卡片里的 `getChatMessages` 是**同步调用**的
  （`const m = getChatMessages("0", ...)`，没有 await），来不及等 iframe 问完主页面再回答，
  所以必须在建 iframe 的那一刻就把数据一起塞进去。
- `gyTavernBridge` —— 真正干活的：
  - `setChatMessages` → 接到续写工作台的换开场白
  - `triggerSlash('/echo ...')` → 剥掉 `severity=` 这类参数，用谷雨自己的提示条弹出来
  - `getChatMessages` → 返回开场白列表

**`js\03-markdown-feed-tags.js`** —— iframe 里注入兼容层：

- `TavernHelper` 对象 + 一整套**裸函数别名**。卡片绝大多数是直接写 `setChatMessages(...)`
  而不是 `TavernHelper.setChatMessages(...)`，两种写法都得能用。
- 读数据的接口用塞进去的快照同步回答；改状态的接口 postMessage 给主页面执行。
- **没实现的接口一律返回安全空值**（`getVariables`、`eventOn`、`generate` 等），
  并在控制台留一行说明。卡片顶多少个花哨效果，绝不会因为调了个没有的方法就整张崩掉。

**`js\16-story-studio.js`** —— 新增 `ssSwitchOpening(charId, swipeIdx)`：

- 是**换掉**开场那一轮，不是再追加一条（不然点几次菜单就叠出一堆开场白）
- 换完开场仍然排在最前面
- 如果后面已经续写出内容了，会先问一句再换——换开场等于把已经写的东西架空

## 有意没做的

`getVariables`/`setVariables`/`eventOn` 这些**没有接**，只给了安全空值。
它们对应的是酒馆的变量系统和事件总线，谷雨有自己的一套（MVU、宏作用域），
硬对接容易对出错误数据。你手上这 14 张卡没有一张真的用到，等真遇到需要的卡再说。

`setChatMessages` 也只支持 `message_id: 0`（开场白）。谷雨的续写楼层跟酒馆的
`message_id` 不是一套编号，除了"第 0 条＝开场白"这个能对上的语义，
其它一律不猜——猜错就是改错楼层。卡片要改别的楼层时，控制台会留一行说明并跳过。
