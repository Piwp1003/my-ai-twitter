【🎨 皮肤盒子：存一次，以后点一下就换】

【🖼️ 推文 / 日记 / 信件配图：重做了，不再往正文里塞标记】
上一版是让模型自己在正文里写 `[IMG:一句话描述]`。你说得对，这不好：
正文里多出一截标记，而且模型经常忘了写、或者写得不对。
现在改成**跟聊天发图完全同一条路**：

· 内容写完之后**单独问一次**「这条要配什么图」，拿到一句描述，再照这句去取图
  → 正文永远是干净的，也不会出现"忘了写标记就没图"
· 取图那一步用的就是 📷「角色发图片」那一套——图源、接口、参考图全在那儿设，
  这儿**不用再配第二遍**
· 模型觉得这条配图反而奇怪（纯情绪、纯吐槽），会自己回"不配"，那就不配

**你自己选用哪个**（设置 → 互动与描写 →「💬 聊天补丁」）：
· 三个地方各一个开关：推文配图 / 日记配图 / 信件配图，**默认都关**
· 用哪一档取图：跟聊天一样（这个角色在 📷 里设的那档）／ 图库里挑 ／ 真生图 ／ 网上搜
· 多少条配一次（%）：100 = 每条都配，30 = 大概三条里配一条。生图那档很花钱，建议调低
⚠️「只发卡片」那一档是纯文字描述，配图没意义——选了它或者关着，这儿就不配图。

实现上：推文写进 `post.mediaUrl`（项目本来就会画），
日记/信件那两个详情页原本没有放图的地方，是**画完之后自己补一张进去**的，
没有改 js/08 的任何渲染代码。每条只考虑一次（打了 `gyArt` 标记），不会反复花钱。

因为不再往 prompt 里塞话了，「注入内容管理」里那一组也跟着撤掉了——
它现在不占任何注入，只在内容写完之后多问一次。

⚠️ 体检踩的坑：场景 key 必须写成**字面量**。
`gyInjectInSceneSoft(k, () => askArt(...))` 这种传变量的写法，
场景覆盖体检是静态扫的、认不出来，会报"这个函数没挂场景"。拆成三个 if 就好了。

【💬 聊天补丁】（设置 → 互动与描写 →「💬 聊天补丁」，四件小事各开各的）

① 🖐️ **手动模式下，攒着的几句当一条回**（默认开）
   你连着说三四句再让 TA 回，以前 TA 常常一句一句分开答，出来几条意思差不多的车轱辘话。
   现在会明确告诉它：这几句是**一口气说完的一条话**，整体回一次，不要每句都回一遍、
   也不要把同一个意思换几种说法重复说。只说了一句时这段不加（不白占 prompt）。

② 👥 **群聊里打 @ 弹人名**（默认开）
   在群聊输入框打一个 @，底下弹出这个群的成员 +「所有人」，打半个名字会筛，点一下补全。
   群里人一多，手打名字很容易打错——打错了那个人根本不会被叫到。1v1 里不弹。

③ 🧭 **TA 也可以去群里说话，不是只能来找你**（默认关）
   自主模式的动作表里多一项「去某个群里说句话」：TA 看几个群最近聊到哪儿了，
   挑一个此刻真的会开口的群，对着群里**另一个角色**说一句（或者只是感慨一句）。
   要这个角色开了自主模式 + 这个开关打开才会发生。

④ 🖼️ **推文 / 日记 / 信件也能配图**（默认关）
   让 TA 在这三个地方写 `[IMG:一句话描述]`，页面上就地换成一张图卡。
   图从哪儿来跟聊天发图**共用同一套**（只发卡片 / 你喂的图库 / 真生图 / 网上搜），
   在「📷 角色发图片」里定，不用再配一遍。
   实现上没动任何渲染函数——画完之后扫一遍页面，看到 [IMG:] 就换成图卡，
   同一张描述在这次会话里只取一次图。

【🧾 都在「注入内容管理」里列着】
· ①的那段提醒 → 可以单独关
· ④的写法说明 → 新增一组「🖼️ 推文/日记/信件配图」，只在那三场出现，私聊里不给
· ③ → 新增一场「👥 TA 自己去群里说话」，能单独设它读多少东西

【📞 通话小窗能拖走了】
按住小窗拖到屏幕任何地方，位置**记在本地**，下次缩起来还在那儿。
⚠️ 拖动和"点一下回到通话"分开了：动了超过 4px 才算拖，
否则松手那一下的 click 会把通话窗又打开（写的时候真踩了）。

【📞 能给 TA 打电话了】
入口：聊天框 **⋮ 里那颗 📞**。点了就打，不受任何开关拦

   也可以填一个 OpenAI 格式的 `/v1/audio/speech`（地址/密钥/模型/音色/语速都在 ⚙️ 里，

③ **我也说话** —— 加上浏览器的麦克风识别，你对着说就转成文字发过去。
   ⚠️ 准不准全看浏览器；打包成 APK 之后多半用不了，那时它只会弹个提示，不会崩。

　 于是你明明填了地址，一个请求都没发出去，页面上还什么都不说。

    async function save() { try { if (LF) await LF.setItem(...); } catch (e) {} }

两个毛病，而且**都不出声**：
 ① localforage 拿不到时 LF 是 null，那句 `if (LF)` 直接跳过——
    什么都没存，一声不吭；
 ② 真写失败了（无痕模式、配额满、打包成 exe/APK 后 IndexedDB 被限制），
    catch 把错误吞掉，你只看到"改的设置怎么又变回去了"，连个提示都没有。

现在统一走一个带兜底的存档口：先 localforage，不行退 localStorage
（只镜像 300KB 以内的小数据，免得把图片音乐塞爆 5MB 配额），
两条路都断才算真失败——**真失败会弹提示告诉你**，而不是假装存上了。

实测：把 localforage 整个掐掉（模拟打包环境），改联网探索的设置、刷新，
设置照样在。以前这种情况下是彻底丢失的。

【🩺 新增两个体检】
· 设置持久化：把 9 个设置面板里的控件逐个改值 → 刷新 → 对比，
  谁回退了就报谁。现在 63 个控件全绿。
· 后台开关 71 个 + 活人感 14 个参数，也是同样的改-刷-对，全绿。

顺带说明：我这边（浏览器 + 正常 localforage）测下来联网探索本来就能存，
所以你遇到的多半正是上面那条「静默失败」——打包环境里存储受限，
